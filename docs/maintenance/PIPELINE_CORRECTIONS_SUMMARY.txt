ISSUE #1: INVALID DOCKER TAG FORMAT
───────────────────────────────────────────────────────────────────────────────
Error: invalid tag "ghcr.io/spmahapatra/rick-morty-api-helm:-9f4894c": invalid reference format

Problem:
  • Docker metadata action generating SHA tags with leading dash
  • Format: :-9f4894c is invalid in Docker
  • Caused by type=sha with branch prefix on tag events

Solution Applied:
  ✓ Removed type=sha from metadata action
  ✓ Changed to explicit value parameter
  ✓ Use semver format with extracted version
  ✓ Add only valid tags: v1.2.3, latest, 1.2, 1

Before:
  tags: |
    type=ref,event=branch
    type=semver,pattern={{version}}
    type=semver,pattern={{major}}.{{minor}}
    type=sha,prefix={{branch}}-              ← PROBLEMATIC
    type=raw,value=latest

After:
  tags: |
    type=semver,pattern={{version}},value=${{ steps.extract-version.outputs.version }}
    type=semver,pattern={{major}}.{{minor}},value=${{ steps.extract-version.outputs.version }}
    type=raw,value=latest

Result:
  ✅ No more invalid tags
  ✅ Clean semantic versioning
  ✅ Multi-platform builds work correctly

ISSUE #3: MISSING REGISTRY PREFIX
───────────────────────────────────────────────────────────────────────────────
Problem:
  • Fast-track docker build missing registry prefix
  • Image tags weren't in full format
  • Inconsistent with GHCR tagging

Solution Applied:
  ✓ Added ${{ env.REGISTRY }} prefix
  ✓ Full tag format: ghcr.io/user/repo:tag

Before:

  Results: rick-morty-api-helm:v0.1.0        ← missing registry

After:

Result:
  ✅ Consistent registry prefix
  ✅ Proper Docker image format
  ✅ Works with all registries


ISSUE #4: CLEANUP ERROR HANDLING
───────────────────────────────────────────────────────────────────────────────
Problem:
  • Cleanup step could fail if docker-compose wasn't running
  • Failed cleanup would fail the entire job
  • Non-critical operation causing workflow failures

Solution Applied:
  ✓ Added || true to cleanup command
  ✓ Prevents non-critical failures
  ✓ Cleanup always completes

Before:
  - name: Cleanup
    run: docker-compose down --volumes        ← fails if not running

After:
  - name: Cleanup
    run: docker-compose down --volumes || true    ← always succeeds

Result:
  ✅ Cleanup failures don't fail workflow
  ✅ Robust error handling
  ✅ Non-critical operations protected
